# Mistake Library - Two Pointers and Sliding Window

Use this as a debugging checklist. For each mistake, identify the cause before changing code.

## Recognition Mistakes

| Mistake | Why it happens | How to detect it | Rule to prevent it |
| --- | --- | --- | --- |
| Every subarray problem is treated as sliding window | keyword-driven pattern matching | negative values or non-monotone validity appear | prove monotonicity first |
| Every two-number problem is treated as two pointers | confusing the story with the structure | data is unsorted and original order matters | choose hashmap or sort with index retention |
| k automatically means fixed window | assuming the number is a window length | k refers to frequency, rank, or operations instead | identify what k measures |
| A heap is used for every multi-sequence problem | overlooking the two-source case | only two sorted frontiers exist | compare two pointers directly |
| Prefix sum is ignored because a window exists | forcing a live window on arbitrary queries | ranges are nonlocal or exact negative sums appear | match the state to the query |

## Reasoning Mistakes

| Mistake | Why it happens | How to detect it | Rule to prevent it |
| --- | --- | --- | --- |
| Moving left or right without a proof | memorizing templates | cannot name what candidates are discarded | write the pointer-move proof in one sentence |
| Updating the answer while the invariant is broken | loop order was copied without understanding | dry run shows an invalid window being counted | restore validity before the answer update |
| Using one shrink step instead of a while loop | assuming one removal is enough | a window remains valid or invalid after one move | shrink repeatedly when the objective requires it |
| Forgetting that positive values are a precondition | treating sum behavior as universal | negative input changes the sum unpredictably | test a negative counterexample |
| Confusing source frontiers with top-k candidates | same heap size appears in both patterns | heap stores multiple items from one source | one slot per source means k-way merge |

## Implementation Mistakes

| Mistake | Why it happens | How to detect it | Rule to prevent it |
| --- | --- | --- | --- |
| Off-by-one in a fixed window | mixed inclusive and half-open conventions | first or last window is missing | write the window length equation |
| Removing the wrong value | using right - k inconsistently | sums drift after the first slide | identify the leaving index explicitly |
| Forgetting to remove a frequency key at count zero | state tracks keys, not counts | distinct count never decreases | decrement count, then remove the key |
| Duplicate triplets in 3Sum | duplicate handling added too late | equal adjacent values produce repeated results | skip fixed and pointer duplicates |
| Integer overflow in sums or products | input bounds were ignored | answer is negative or wraps | cast before addition and use long |
| Overwriting unread values during merge | writing from the front into nums1 | later comparisons use changed data | fill from the back when capacity overlaps |
| Comparator overflow | subtracting large ints | ordering fails on extreme values | use Integer.compare or Long.compare |

## Complexity Mistakes

| Mistake | Why it happens | How to detect it | Rule to prevent it |
| --- | --- | --- | --- |
| Calling a nested while loop O(n²) automatically | counting syntax instead of pointer movement | both pointers only move forward | charge each element once per boundary |
| Forgetting sorting cost | focusing only on the pointer scan | array is sorted inside the method | include O(n log n) |
| Assuming all sliding windows are O(n) | ignoring expensive state updates | each move rescans or sorts the window | measure add/remove cost |
| Ignoring heap factor in k-way merge | treating k sources like two | heap operations appear in the loop | include O(N log k) |

## Interview Mistakes

| Mistake | Why it happens | How to detect it | Rule to prevent it |
| --- | --- | --- | --- |
| Coding before stating the invariant | wanting to reach a familiar template | cannot explain what the pointers mean | say the invariant before writing the loop |
| Giving only trigger words | memorization-first preparation | explanation says "contains k, so use window" | connect structural property to state |
| Not stating preconditions | optimized solution sounds universal | answer ignores sortedness or positivity | say the precondition explicitly |
| No hostile dry run | testing only the happy path | code fails on empty, duplicate, or boundary cases | test at least two hostile cases aloud |
