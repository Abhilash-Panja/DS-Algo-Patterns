# Pattern Decision Tree

Use this tree after stripping the story. Do not choose a pattern from a keyword alone.

~~~text
Are selected elements required to be contiguous?
│
├── No
│   ├── Is this an exact pair lookup in unsorted data?
│   │      └── Yes → Hashmap Two Sum, not sorted two pointers
│   └── Is this a linked-list position/cycle problem?
│          └── Yes → Fast/slow pointers, adjacent topic
│
└── Yes
    │
    ├── Is the length fixed at k?
    │      └── Yes → Fixed-size sliding window
    │
    ├── Is the length variable and the condition monotone
    │   as the window expands/shrinks?
    │      ├── Yes → Variable-size sliding window
    │      └── No
    │          ├── Exact sum with negative values?
    │          │      └── Prefix sum + hashmap
    │          ├── Window maximum/minimum?
    │          │      └── Monotonic deque
    │          └── Maximum subarray sum?
    │                 └── Kadane's algorithm
    │
    ├── Is the main object a pair/triple and is data sorted
    │   or safe to sort?
    │      └── Yes → Sorted opposite-direction pointers
    │
    ├── Are there multiple sorted sources?
    │      ├── Two sources → two-pointer merge
    │      └── More than two → k-way heap frontier
    │
    └── Must the result be compacted or partitioned in-place?
           ├── Stable output prefix → read/write pointers
           └── Order may change → partition pointers from both ends
~~~

## Boundary Questions

### Fixed versus variable window

If every candidate has exactly k positions, do not write a shrinking loop. If the answer is the longest or shortest valid length, define feasibility before coding.

### Sliding window versus prefix sum

If a window sum becomes invalid, ask whether shrinking always changes the sum in the required direction. Negative numbers are the classic reason the answer is no.

### Sorted Two Sum versus hashmap Two Sum

Sorting is useful only if order can be changed or original indices are retained. If the array must remain in original order, a hashmap is often the cleaner structure.

### Two-source merge versus k-way merge

Two pointers compare two current frontiers. A heap is justified when many source frontiers must be compared repeatedly.

### Read/write versus opposite pointers

If accepted values must retain relative order, use a forward write pointer. If values can be rearranged, a partition from both ends may reduce writes.
