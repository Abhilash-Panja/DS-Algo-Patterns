# Approaching an Unknown Two-Pointer or Sliding-Window Problem

The goal is not to recognize a keyword. The goal is to extract the structure and prove a pointer movement.

## 1. The 30-90 Second Protocol

### Step 1 - Strip the story

Write only:

- input;
- output;
- whether elements must be contiguous;
- whether original order matters;
- mathematical objective;
- constraints.

Example:

~~~text
"Choose a continuous period with at most two categories and maximize its length"
becomes
"Find the longest contiguous interval containing at most two distinct values."
~~~

### Step 2 - Identify the shape

Ask:

- Is this a contiguous region?
- Is it a pair or triple?
- Are there multiple sorted sources?
- Is the output an in-place filtered prefix?
- Is the data already sorted or safe to sort?

### Step 3 - Find the expensive repeated operation

Typical bottlenecks:

- recomputing every subarray sum;
- checking every pair;
- rescanning every source head;
- shifting elements after every deletion;
- rebuilding a frequency count for each substring.

### Step 4 - Look for the property that makes movement safe

Do not continue until you can name one:

- fixed length;
- positive values make a sum monotone;
- sorted order makes value changes monotone;
- processed prefix is already final;
- each source is individually sorted.

If you cannot state the property, you do not yet have a valid pointer algorithm.

### Step 5 - Ask what state must survive

Examples:

- running sum;
- frequency map;
- distinct-value count;
- last-seen positions;
- left and right frontier values;
- write position;
- one current node per sorted source.

### Step 6 - Map to candidate patterns

Use the decision tree in the next file. Keep two or three candidates alive until the invariant eliminates the wrong ones.

### Step 7 - Eliminate similar patterns

Ask:

- Is the candidate contiguous?
- Is the condition monotone?
- Are negative numbers present?
- Is original order required?
- Are there two sources or k sources?
- Is the heap storing answer candidates or source frontiers?

### Step 8 - State the invariant before code

Complete this sentence:

> At the beginning/end of every iteration, ...

If the sentence is vague, the code will likely be vague.

### Step 9 - Dry run a hostile example

Use one of:

- all duplicates;
- no valid answer;
- answer at the first or last position;
- negative values;
- repeated equal values;
- one source becoming empty;
- the window shrinking multiple times in one iteration.

### Step 10 - Explain complexity by pointer movement

Do not say "nested loops, so O(n²)" automatically. If left and right each move only forward, total movement is O(n). If a sort is required, include O(n log n). If k source frontiers use a heap, include O(N log k).

## 2. Topic-Specific Diagnostic Questions

### Contiguity

> Can I remove an element from the middle and still call the candidate a valid window?

If no, sliding-window reasoning may apply. If yes, it may be a subset or subsequence problem instead.

### Fixed or variable length

> Is k fixed by the statement, or is the answer itself the window length?

Fixed length suggests one add and one remove. Variable length requires a feasibility invariant.

### Monotonicity

> If I expand right, does the condition move predictably? If I remove left, can I predict the direction of change?

If no, do not force a variable window.

### Sorting

> If I sort, do I preserve everything the output asks for?

If original indices or original order matter, store the index or choose a hashmap/alternative.

### Pair elimination

> After comparing the current two values, can I prove an entire row or column of pairs is impossible?

If yes, opposite-direction pointers may be valid.

### Frontier state

> Does each sorted source expose only one possible next item?

If yes, use two pointers for two sources or a heap for k sources.

### In-place state

> Can the answer-so-far be represented as a prefix of the same array?

If yes, a read/write pointer may eliminate extra space.

## 4. Interview Explanation Skeleton

> I first reduce the problem to [contiguous window / sorted pair search / source frontier / in-place prefix]. The useful property is [fixed length / monotone feasibility / sorted order / processed-prefix safety]. I maintain [state], and my invariant is [invariant]. When [condition], I move [pointer] because [proof]. Each pointer moves [at most once / through its source once], so the complexity is [complexity].

## 5. Red Flags

Stop and reconsider if:

- you are moving a pointer without explaining what becomes impossible;
- a variable window contains negative numbers and the sum condition is not monotone;
- you sorted but lost the required original index;
- you used a heap for two sorted sources without needing one;
- you used two pointers on an unsorted pair problem only because the phrase "two numbers" appeared;
- you update the answer before restoring the invariant;
- duplicate handling is an afterthought.

## 6. What To Do When No Pattern Fits

A failed fit is useful information. Check adjacent techniques:

- exact sum with negative values: prefix sum plus hashmap;
- maximum subarray: Kadane;
- window min/max: monotonic deque;
- unsorted pair lookup: hashmap;
- k-way sorted frontier: heap;
- order-sensitive search: binary search or dynamic programming;
- linked-list cycle/middle: fast/slow pointers.

The correct solution is often the one that explains why a tempting two-pointer solution is invalid.
