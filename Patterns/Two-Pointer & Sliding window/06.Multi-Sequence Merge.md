# Pattern 5 - Multi-Sequence Merge

## 1. What This Pattern Actually Is

> Maintain the current frontier of each sorted sequence and repeatedly advance the sequence whose frontier contributes the next output value.

For two sorted sequences, two pointers are enough. For k sequences, one pointer per source plus a min-heap is usually the correct generalization.

## 2. Why This Pattern Exists

Concatenating all values and sorting ignores the order already present in each source.

~~~text
Collect every value and sort
        ↓
O(N log N)
        ↓
Each source is already sorted
        ↓
Only the current head of each source can be the next output
        ↓
Two sources: O(N + M)
k sources: O(N log k) with a heap
~~~

## 3. Recognition Signals

Ask:

1. Are there two or more independently sorted arrays, lists, or streams?
2. Is the goal to merge, compare, intersect, or find the next smallest/largest item?
3. Does each source expose a current frontier?
4. After choosing a frontier, does only that source need to advance?
5. Is the number of sources two or k?

## 4. Trigger Words - But Do Not Depend On Them

"Merge sorted", "combine streams", "intersection of sorted lists", "chronological feeds", and "next smallest event" are common signals. The story may involve logs, files, timelines, or ranked sources; the structural clue is one-way order inside each source.

## 5. The Invariant

> Every unmerged value is at or after the current pointer of its source, and the next output value must be the smallest current frontier among the sources.

For two sources, comparing the two frontiers is enough. For k sources, the heap stores the smallest frontier from each nonempty source.

## 6. Derive the Algorithm Slowly

### Two sources

1. Start at the first value of each source.
2. Append the smaller frontier.
3. Advance only that source.
4. When one source is exhausted, append the remainder of the other.

### k sources

1. Insert the first item from each nonempty source into a min-heap.
2. Pop the smallest frontier.
3. Append it.
4. Insert the next item from the same source.
5. Repeat until the heap is empty.

## 7. Why Not Sort Everything?

The source order is valuable information. Sorting all N values costs O(N log N) and uses extra memory if materialized. A two-pointer merge is linear for two sources. A heap uses O(k) frontier state for k sources and costs O(N log k).

## 8. Core Java Templates

### Merge two arrays

~~~java
static int[] mergeSorted(int[] a, int[] b) {
    int[] result = new int[a.length + b.length];
    int i = 0;
    int j = 0;
    int write = 0;

    while (i < a.length && j < b.length) {
        if (a[i] <= b[j]) {
            result[write++] = a[i++];
        } else {
            result[write++] = b[j++];
        }
    }

    while (i < a.length) result[write++] = a[i++];
    while (j < b.length) result[write++] = b[j++];

    return result;
}
~~~

### k-way heap frontier

PriorityQueue<int[]> pq =

~~~

Use Integer.compare rather than subtracting comparator values to avoid overflow.

## 9. Code Fingerprint

~~~text
while both sources have values:
    choose the smaller current frontier
    advance only that source

append the remaining suffix
~~~

For k sources, the fingerprint becomes poll one frontier, then push the next item from that same source.

## 10. When Not to Use It

- The sources are not sorted and cannot be sorted independently.
- You need a global top-k filter rather than a full merge.
- The number of sources is two but a heap adds unnecessary overhead.
- The problem requires arbitrary updates to the middle of a source.
- The desired output is not ordered and a hashmap gives a simpler solution.

## 11. Similar Pattern Comparison

| Question | Two-sequence merge | k-way heap merge | Top-k heap |
| --- | --- | --- | --- |
| Heap needed? | no | usually yes | often yes |
| State represents | one frontier per source | one frontier per source | candidate answers |
| Pop meaning | choose smaller pointer | choose smallest current source head | evict weakest current candidate |
| Source order | essential | essential | not required |
| Typical complexity | O(N + M) | O(N log k) | O(N log k) |

## 12. Deep Worked Example - Merge Sorted Array

Problem: Merge two sorted arrays into one sorted array. The first array has enough empty space at its end for the second array.

### Strip the story

- Input: sorted values in nums1 and nums2.
- Output: nums1 containing every value in sorted order.
- Constraint: nums1 has unused capacity at the end.

### Brute force

Append nums2 to nums1 and sort. This costs O((N + M) log(N + M)).

### Structural observation

The largest remaining value belongs at the back. If we write from the back, we do not overwrite unread values in nums1.

### Invariant

After each write, the suffix after write contains the largest values in their final positions, and the unread prefixes of both arrays remain sorted.

### Dry run

For nums1 = [1, 2, 3, 0, 0, 0] and nums2 = [2, 5, 6]:

~~~text
compare 3 and 6 → write 6 at the back
compare 3 and 5 → write 5
compare 3 and 2 → write 3
compare 2 and 2 → write 2
copy remaining 2 and 1
result: [1, 2, 2, 3, 5, 6]
~~~

### Java code

~~~java
static void merge(int[] nums1, int m, int[] nums2, int n) {
    int i = m - 1;
    int j = n - 1;
    int write = m + n - 1;

    while (j >= 0) {
        if (i >= 0 && nums1[i] > nums2[j]) {
            nums1[write--] = nums1[i--];
        } else {
            nums1[write--] = nums2[j--];
        }
    }
}
~~~

### Complexity

Each value is moved at most once: O(N + M) time and O(1) extra space.

### Interview explanation

> Both inputs are sorted, so I compare their largest unread values. Writing from the back avoids overwriting the unread part of nums1. The suffix already written is final, and each pointer only moves left, giving linear time and constant extra space.

## 14. Follow-Up Training

- If the sources arrive as streams, keep only the current frontier and a way to request the next item.
- If sources are descending, reverse the comparison or iterate from the other side.
- If k is large, analyze heap cost and input access carefully.
- If duplicates should be collapsed, add a last-emitted-value invariant.
- If the task asks for only the first k outputs, stop after k frontier selections.
